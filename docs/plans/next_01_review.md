## A. 필수 수정

1. **합격 기준을 숫자로 쓴다.** 예: 벤치 TTS 첫 소리 P50 ≤ 600ms, 본문 첫 오디오(e2e) P50 개선 ≥ 300ms, 청크 사이 무음 > 0 인 턴 0/20. 미달이면 기본값 끔으로 두고 끝낸다.
2. **1초 목표에 못 미친다고 적는다.** e2e P50 1798ms에서 예상 -450ms를 빼도 약 1350ms다. 남은 차이와 다음 후보를 한 줄로 쓴다.
3. **-450ms 근거를 고친다.** 단독 507ms는 `sentences_ko.txt` 40문장(LLM 유휴), 991ms는 짧은 첫 청크(LLM 동시) 값이다. 문장 세트가 달라 직접 빼면 안 된다. "확인하지 않았다"로 쓴다.
4. **2차 요청 시점을 하나로 정한다.** 결론(첫 TTS 합성 뒤), §1(첫 오디오 프레임), PLAN §2(TTS가 끝난 뒤)가 서로 다르다. 첫 프레임 시점이면 1청크 나머지 합성과 다시 경합한다. 시점별 비교를 벤치 항목에 넣는다.
5. **프롬프트·청커 변경과 양보를 따로 측정한다.** 청커가 군더더기 쉼표에서 안 자르면 첫 청크가 길어져 첫 청크 시각이 늦어질 수 있다. 순서: (a) 프롬프트·청커만 → (b) + 양보. 각 단계에서 첫 청크 길이·"네," 시작 비율(기준 3/20)을 기록한다.
6. **`web_e2e.py` 실행법을 고친다.** 이 스크립트는 `sys.argv[1]`가 필수이고, 데모 서버가 먼저 떠 있어야 한다. 서버를 `--llm-yield`/`--no-llm-yield`로 각각 띄우는 절차와 기준선 조건(합성음 마이크 4문장 × 4회, n=16)을 적는다.
7. **"청크 사이 공백"을 정의한다.** `first_audio_bench.py`는 재생하지 않는다. "1청크 오디오 길이 − (2청크 첫 프레임 시각 − 1청크 첫 프레임 시각)"처럼 계산식을 정한다.

## B. 빠진 위험 (§4에 추가)

1. **선행 생성(`PendingTurn`)**: 확정 전 프레임은 `_Outbox`에 쌓인다. 2차 요청 계기는 "재생"이 아니라 "TTS 프레임 생성"이어야 한다. `abort` 시 1차·2차 모두 취소한다.
2. **이어쓰기 경계**: MTP로 1차 스트림이 첫 청크 뒤 글자를 더 받을 수 있다. 이 글자를 접두사에 넣을지 버릴지 정해야 한다. 아니면 중복·누락이 생긴다. 문장 사이 공백도 확인한다.
3. **대화 기록·`hint`**: 기록에는 1차+2차를 이어 붙인 한 답으로 저장한다. 끼어들기 시 들린 부분만 남기는 기존 처리와 맞춘다. 2차 요청에도 같은 시스템 프롬프트·`hint`를 넣는다 (접두사 캐시 조건).
4. **채팅 템플릿**: Qwen 템플릿의 생각 모드 끔(빈 `<think>` 블록)과 `continue_final_message`·`add_generation_prompt=False` 조합을 확인하지 않았다. 1개 요청으로 먼저 확인한다.
5. **vLLM 중단 확인 방법**: 연결을 닫은 뒤 실제로 요청이 중단됐는지 `/metrics`의 실행 중 요청 수로 확인하는 절차를 넣는다.
6. **2차 TTFT 추가**: 2차 요청은 프리필을 다시 한다 (TTFT P50 224ms, 접두사 캐시 미적용 시 더 길다). `max_tokens` 256을 1차·2차에 어떻게 나눌지 정한다.
7. **운영 PC**: GPU 2장이면 이 경로가 필요 없을 수 있다 (PLAN §2). 개발 장비 수치를 최종 수치로 쓰지 않는다 (`CLAUDE.md` §4). 5주차 GPU 분리 측정에서 켬/끔을 다시 잰다고 적는다.

1. **TTS 첫 소리에 서버 잠금 대기가 섞였다.** 벤치는 2청크 TTS를 첫 프레임 뒤 `cancel()`한다. CosyVoice 서버는 다음 쓰기에서야 끊김을 알고, 그동안 잠금(`lock`)을 쥔다. 다음 모드의 1청크 요청은 이 잠금을 기다린다.
   - 서버 로그 "첫 청크"(잠금 획득 뒤 측정): 양보 1청크 **약 495ms** (예: 01:21:49 497ms, 01:22:05 499ms). 동시 1청크 약 1000ms
   - 벤치 값: 양보 942·968ms, 동시 1385ms. 차이 약 400~450ms가 잠금 대기다
   - 예: 동시 2청크 첫 프레임 01:21:47.3 → 다음 잠금 획득 01:21:48.7. 취소 뒤 약 1.4초 동안 합성이 계속됐다

   - 직접 확인: `chat_template_kwargs` 안에 넣으면 프롬프트 38토큰, 출력이 넣지 않은 요청과 같다. 요청 최상위에 넣으면 29토큰이고 " 수면 부족은…"으로 이어 쓴다
   - 그래서 1b의 2차 요청은 새 답을 처음부터 만든 것이다. 2청크 문장이 1청크와 겹칠 수 있다. 벤치가 2청크 문장을 출력하지 않아 확인하지 못했다
   - `tests/test_llm_openai.py`의 신규 시험 3개가 잘못된 위치를 정답으로 고정한다

|---|---|---|
| TTS 첫 소리 P50 ≤ 600ms | ❌ 942 / 968ms | **측정 오류일 가능성이 높다.** 서버 쪽 약 495ms라 통과 수준이다. 벤치 값으로는 확인하지 않았다 |
| 합계 단축 ≥ 300ms | ✅ 599 / 567ms | **판단 불가.** 기준선이 부풀었고, 계획의 절대 기준(≤ 1350ms)을 보지 않았다 |
| `gap_ms > 0` 0/20 | ❌ 19/20, P50 615 / 651ms | **진짜 미달로 본다.** 2청크 TTS 앞 요청은 끝까지 받은 1청크라 잠금 대기가 없다. 공백은 2차 TTFT(캐시 0%) + 2청크 생성 + 2청크 TTS 첫 소리(서버 약 610~718ms)다. 이어쓰기를 고쳐도 이 구성은 남는다 |

- 결론: 계획의 중단 조건대로 **2단계는 시작하지 않는다.** 다만 양보는 1청크 TTS를 약 500ms 줄이고, 첫 문장 뒤에 약 0.6초 공백을 만든다 (서버 로그 기준). 공백을 허용할지는 청취로 정할 사용자 결정이다

### K. 수정 항목

1. `openai_stream.py`: `continue_final_message`·`add_generation_prompt`를 요청 최상위 필드로 옮긴다. 신규 시험 3개도 같이 고친다.
2. 벤치 잠금 대기 제거: 측정용이 아닌 2청크 TTS는 끝까지 받거나, 다음 시험 전에 TTS 서버가 빌 때까지 기다린다. 서버 "첫 청크" 값과 벤치 값이 맞는지 같이 기록한다.
3. 벤치 `idle` 모드: LLM 스트림을 `aclose()`로 닫는다. 시험 사이에 vLLM 실행 중 요청 수가 0인지 확인한다.
4. 벤치 판정: 합계는 계획대로 절대 기준(≤ 1350ms)도 본다. 2청크 문장을 출력해 이어쓰기 중복·누락을 확인한다.
5. (권장) 1a 부분(`chunker.py`, `PROMPT_NO_FILLER`, 청커 시험)은 따로 먼저 커밋할 수 있다. 커밋은 사용자 요청 시에만 한다.
6. (권장) 고정 프롬프트에서도 "음, 좋은 마음이시네요."처럼 "음,"으로 시작하는 첫 청크가 나온다. 파이프라인의 군더더기 제거(`_LEADING_FILLER`)가 "음,"도 지우는지 확인한다.
7. (권장) CosyVoice 서버가 취소 뒤 약 1.4초 동안 합성을 계속한다. 이것은 실제 끼어들기(barge-in) 뒤 첫 응답도 늦출 수 있다. 별도 항목으로 기록한다 (확인하지 않았다).
