## 2. 화면: 개발 모드와 데모 모드 (개별 기능 토글 포함)

### 2.1 공통 규칙

1. 모드는 세션(브라우저 탭)마다 둔다. 서버 기본값은 실행 인자 `--default-mode`로 정한다. 기본값은 `demo`다 (저장하지 않는 쪽이 기본)
2. 브라우저가 모드와 개별 기능 토글 설정(`prefs`)을 `localStorage`에 기억한다. 재연결 뒤에 `config`로 다시 보낸다. 지금은 재연결하면 설정이 기본으로 돌아간다 (`Claude/docs/STATE.md` 알려진 문제)
3. 모드 전환 경로는 2개다: 화면 구석의 모드 토글/설정 버튼(`⚙️`), 음성 명령 (§3.1)
4. 데모 모드에서 기본으로 숨기는 것은 화면 표시만이다. 서버 대화 처리(턴 종료, barge-in, 선행 생성)는 두 모드가 같다. 다만 사용자가 데모 모드에서도 개별 기능을 하나씩 켜고 끌 수 있도록 **접이식 설정 패널(`⚙️ 설정`)**과 **음성 명령**을 제공한다 (§2.2)
5. 서버 파일 로그(`logs/dev/`, `endpoint_log/`) 저장 여부는 모드(`dev`에서만 저장, `demo`는 저장 안 함)를 따른다 (§2.4). 데모 모드에서 화면의 `개발 정보 표시` 토글만 켠 경우에는 화면에만 보이고 파일 로그는 남기지 않는다

### 2.2 데모 모드 표시 항목과 개별 기능 토글 (추천안 기본값 확정)

- **자리표시 영역 (avatar placeholder)**: 화면 전체(또는 중앙 대형 카드)를 쓴다. 나중에 메타휴먼 화면이 들어갈 자리다
  - 영역 안에 상태를 색과 짧은 글로 보인다: 대기 / 듣는 중 / 생각 중 / 말하는 중 / 안전 안내. 입력은 기존 `avatar_state`와 `session_state` 메시지다
  - 말하는 중에는 재생 음량 막대를 보인다 (입모양 대신)
  - 최초 접속 후 자리표시 영역을 1회 터치하면 브라우저 오디오(`AudioContext`)와 마이크 권한이 활성화된다 (`--wake`가 켜져 있으면 대기 청취 진입, 꺼져 있으면 즉시 세션 시작)
- **예외 표시 (영역 밖에 작게 보인다 — §8 결정 4 확정)**:
  1. **"AI 마음 건강 도우미"** 고지. AI 기본법 §31①③ 때문에 기본으로 항상 보인다 (`LEGAL_REVIEW.md` P0-1, P1-3 반영)
  2. **카메라 켜짐 표시** (`카메라 켜짐`). 카메라를 쓸 때만 보인다 (§4.4) + `--wake` 대기 중일 때는 **대기 마이크 켜짐 표시** (`마이크 대기 중`)를 보인다
  3. **연결 상태 표시** (연결 끊김·재연결 중·RTT)
- 동의 안내(§4.4)나 AI 고지 해제 경고가 필요할 때만 영역 위에 큰 글씨 오버레이로 덮는다
- **데모 모드 개별 기능 토글 (`⚙️ 설정` 접이식 패널 및 음성 명령 — §8 추가 요구 반영)**:
  데모 모드에서도 화면 구석의 `⚙️ 설정` 버튼을 열거나 음성 명령으로 아래 6개 기능을 하나씩 켜고 끌 수 있다. 기본값은 모두 확정된 추천안이다:

| 토글 키 (`prefs`) | 화면 라벨 | 데모 모드 기본값 | 개발 모드 기본값 | 동작 및 제약 |
|---|---|---|---|---|

### 2.4 개발 로그 파일

- 위치: `logs/dev/YYYYMMDD/<session_id>.jsonl`. `session_id`는 임의 값이다. 사람을 가리키지 않는다. `logs/`를 `.gitignore`에 넣는다
- 한 줄 = 한 턴 또는 한 이벤트. 턴 줄의 필드:
  - `ts`, `session_id`, `utt_id`, `turn_id`, `mode`
  - `transcript`, `stt_id`, `stt_ms`, `emotion`, `event`, `face`(요약만), `hint_rule`
  - `intent`(의도·등급·규칙), `llm_text`, `spoken_text`, `interrupted`
  - `trace`(모든 마크의 ms), `turn_eval_reason`, `barge`(이벤트 목록)
- 남기지 않는 것: 오디오, 영상, hint 문장 원문, 대기 중(§3.5) 비명령 전사, 인증 토큰
- 기존 판단 로그(`endpoint/turn.py` 445행, `bench/results/endpoint_log/`)도 개발 모드(또는 단위 시험에서 `endpoint_log_dir`을 명시 주입한 경우)에서만 쓴다. `LEGAL_REVIEW.md`의 "지금 할 일"과 같다
- 보유기간: 서버 시작 때와 하루 한 번 오래된 파일을 지운다. 기간은 실행 인자 `--dev-log-days`이며 **기본값은 `7`(7일, §8 결정 3 확정)**이다
- 데모 모드: 파일을 만들지 않는다 (`show_dev_info` 화면 토글을 켜더라도 `mode == "demo"`이면 파일은 쓰지 않는다)
- 개발 로그는 동의한 개발자·시험자의 음성으로만 만든다

### 3.2 의도 분류 방식 (선택지 3개)

1. **(추천·확정) 규칙 분류 + 상태 제한 + 확인 질문**
   - 정규화한 전사 전체가 명령 문형과 맞을 때만 명령이다. 문장 일부에 단어가 들어 있으면 대화다
   - 상태마다 받는 의도를 제한한다 (§3.1 「받는 상태」)
   - 장점: 추가 지연이 거의 없고, 오인식 원인을 규칙으로 추적할 수 있다. 단점: 처음 보는 표현을 놓친다
2. 규칙 + LLM 판별 (규칙이 애매하다고 볼 때만 vLLM에 JSON 분류 요청)
   - 표현 다양성은 좋다. 그러나 요청마다 LLM 첫 토큰 시간이 더해진다 (TTFT P50 224ms, `Claude/docs/STATE.md` 실측 표). 같은 GPU에서 TTS와 경합한다 (`docs/PLAN.md` §1)
3. CPU 소형 분류 모델 (문장 임베딩 + 최근접 예시)
   - 새 모델 의존성과 학습 예시가 필요하다. 8일 일정에 맞지 않는다

추천 1을 쓴다. 놓친 표현은 대화로 처리되므로 위험은 "명령이 안 먹힘"이다. 반대 위험(대화를 명령으로 오인)보다 덜 해롭다.

### 3.3 처리 순서

1. 위기 표현 검사를 먼저 한다. 맞으면 명령으로 보지 않고 대화 경로로 보낸다 (예: "다 끝내고 싶어", "그만 살고 싶어")
2. 정규화한다: 문장부호·SenseVoice 태그 제거, 띄어쓰기 제거, 끝 어미 변형("해/해 줘/해 주세요/해요") 통일. `barge_filter.normalize()`와 Kiwi를 재사용한다
3. 길이를 본다. 어절 수가 상한을 넘으면 대화다. 초기값은 `barge_filter.py`의 `MAX_WORDS = 4`와 같게 둔다 (가설; 개별 기능 토글 문형은 5어절까지 허용 가능)
4. 현재 상태에서 받는 의도의 문형과 맞춘다. 등급을 정한다: 즉시 / 확인 / 대화
5. 결과를 연결 지점 3곳에 쓴다
   - 턴 확정 뒤 `_run_turn`: `pipeline.respond()` 전에 분류한다. 명령이면 LLM을 부르지 않는다
   - 선행 생성 `_on_speculate`: 명령 후보면 선행 생성을 하지 않는다
   - 말하는 중 판별 `_probe_classify`: 맞장구가 아니면 명령인지 본다. `STOP_SPEAKING`이면 끊기만 하고 새 턴을 만들지 않는다
6. 확인 질문이 필요하면 미리 합성한 질문을 재생하고 「확인 대기」 상태로 간다
7. 확인 대기에서 다음 발화가 `CONFIRM_YES`면 실행, `CONFIRM_NO`면 취소다. 다른 말이면 취소하고 그 말을 보통 턴으로 처리한다. 응답이 없으면 시간 초과로 취소한다 (초기값 8초, 가설)

### 3.4 오인식 대비

1. **위기 표현 우선**: "끝내고 싶어"는 `SESSION_END`와 단어가 겹친다. 위기 검사를 먼저 해서 종료 확인 질문을 하지 않는다. 위기 대응 경로 자체는 이번 범위가 아니다 (`docs/PLAN.md` §5, 11월)
2. **전체 일치만**: "그만 좀 하라고 했는데 계속 그래요"는 대화다. 문장 일부 일치로는 명령을 실행하지 않는다
3. **상태 제한**: "그만"은 말하는 중에만 `STOP_SPEAKING`이다. 듣는 중의 "그만할게요"는 `SESSION_END` 후보이고 확인을 받는다
4. **에코 대비**: 확인 질문 문장에 "네·아니요"를 넣지 않는다 (예: "대화를 끝낼까요?"). 스피커 소리가 마이크로 들어와도 대답으로 잡히지 않게 한다. 브라우저 에코 제거(AEC) 효과는 확인하지 않았다 (`docs/STATE.md` §11)
5. **맞장구 필터와 충돌**: 확인 대기 중의 짧은 "네"는 `is_backchannel()`에 걸려 버려질 수 있다. 확인 대기 상태에서는 맞장구 판별보다 확인 응답 판별을 먼저 한다
6. **평가 세트 분리**: 규칙은 `code` 창(`agy Gemini Flash`)이 쓰고, 텍스트 평가 세트는 설계·검토 창이 따로 쓴다. 같은 쪽이 둘 다 쓰면 과적합을 못 본다
7. **STT 오류**: 합성음 기준 SenseVoice CER은 0.133, Qwen3-ASR은 0.072다 (`Claude/docs/STATE.md` STT 비교 행). 실제 음성 값은 확인하지 않았다. 작업 D1 녹음으로 표기 변형을 모아 문형에 넣는다. 자모 단위 근사 일치는 오실행을 늘릴 수 있어 처음에는 쓰지 않는다

### 3.5 음성으로 시작 (대기 청취 — §8 결정 1 확정)

- **기술 제약**: 브라우저는 사용자 동작 없이 오디오 재생(`AudioContext`)과 마이크 권한 요청을 시작하지 않는다. 그래서 페이지를 연 뒤 화면 터치 1회는 남는다. 키오스크 설정으로 없앨 수 있는지는 태블릿 브라우저에서 확인하지 않았다
- **법적 제약**: 대기 중 마이크를 들으면 `LEGAL_REVIEW.md` P0-5(통신비밀보호법 §3·§14)와 충돌한다. 주변 사람의 대화가 서버로 간다
- **확정 방안 (추천안 1 채택)**: **첫 터치 1회 + 대기 청취 (실행 인자 `--wake`로 켬, 연구실 데모에서는 켜고 설정 패널·음성 명령으로 언제든 on/off 가능)**
  - 대기 중에는 화면에 `"마이크 대기 중 ('시작하자'라고 말씀해 주세요)"` 표시를 띄운다
  - 대기 중에는 짧은 발화만 STT에 넣는다. 길이 상한 초기값 2000ms (가설)
  - `SESSION_START`만 받는다 (또는 대기 상태에서 허용된 `MODE_*`, `WAKE_OFF` 등). 다른 전사는 바로 버린다. 개발 모드에서도 파일에 남기지 않고 개수만 센다
  - 10/30 데모(연구실 시연)에서는 켜고, 공공장소 설치 전에는 법률 검토를 받는다

### 3.6 지연 영향

- 규칙 분류는 CPU 문자열 처리다. 합격선: 분류 시간 P99 ≤ 5ms (제안 합격선, 작업 C2에서 잰다)
- 대화 턴은 분류만 더해진다. 본문 첫 오디오 차이 ≤ +50ms를 작업 D2에서 확인한다
- 명령 턴은 LLM을 부르지 않는다. 정지 명령은 `_probe_classify`에서 STT가 끝난 시각부터 `sink.interrupt` 호출까지 ≤ 50ms를 기준으로 확인한다 (`OBJECTIVE.md` §5)
- 말하는 중의 "멈춰"는 지금 맞장구 판별 창(`PROBE_WINDOW_MS = 600`, `barge_filter.py`) 안에서 처리된다. 이 창보다 길게 말하면 지금처럼 끼어들기로 끊는다

## 4. 얼굴 표정 감정을 답변에 쓰는 계획 (실험 작업 — §8 결정 2 확정)

### 4.1 결론과 진행 조건

- 표정 분석은 **브라우저 안에서만** 한다. 영상은 저장하지 않고, 서버로 보내지 않는다. 서버에는 발화 하나당 요약(라벨·신뢰도·관측 비율)만 간다
- 결과는 기존 음성 감정 hint(`llm/hint.py`)와 합쳐 LLM 어조 지시로만 쓴다. 화면 진단·보호자 보고·위기 판정에는 쓰지 않는다
- **진행 조건 (§8 결정 2 확정)**:
  1. 이번 주에 개발용 실험 기능으로 구현한다
  2. 데모 모드와 개발 모드 모두 **초기 기본값은 꺼짐(`face: false`)**이며, 설정 패널(`⚙️`) 또는 `"카메라 켜 줘"` 음성 명령으로 켤 수 있다
  3. 켤 때는 반드시 동의 절차를 거치며, 동의한 개발자·시연자 얼굴로만 시험한다
  4. 공공장소 설치 전에는 법률 검토를 받는다
- 일정 안전장치: 10/26(월) 저녁까지 C3(의도 연결)가 커밋되지 않거나 10/27(화) 오전까지 태블릿이 준비되지 않으면 F1~F3을 먼저 뺀다 (§6)

### 4.2 구조

1. 브라우저가 카메라를 연다 (`getUserMedia({video})`). 동의 전에는 호출하지 않는다
2. 브라우저 안 모델이 낮은 주기로 프레임을 분석한다. 주기 초기값은 F1 측정 뒤 정한다
3. 서버가 보내는 기존 `vad` 메시지(`speaking: true/false`)로 발화 구간을 안다. 그 구간의 결과를 모은다
4. 발화가 끝나면 요약 1개를 보낸다: `{"type": "face_summary", "label", "conf", "coverage", "n_frames"}`
5. 서버는 가장 최근 요약을 세션에 둔다. 선행 생성(`prepare`)이나 턴 확정 때 그 값을 읽는다. **요약을 기다리지 않는다.** 늦게 오면 이번 턴에는 쓰지 않는다
6. `llm/hint.py`의 합침 규칙(§4.6)으로 hint 1개를 만든다. 지금처럼 이번 턴 LLM 요청에만 넣는다

### 4.4 개인정보와 동의 (`LEGAL_REVIEW.md` 반영)

1. **영상 저장·전송 안 함**: 프레임은 브라우저 메모리에서만 처리하고 버린다. 시험으로 확인한다 (F2 통과 기준)
2. **식별 금지**: 얼굴 특징값(embedding)을 만들거나 저장하지 않는다. 사람을 구분하지 않는다 (§2 생체인식정보)
3. **감정은 생체정보로 볼 수 있다** (§6.2, 개인정보위 2021 가이드라인): 동의 항목에 "표정으로 기분을 짐작해 답에 참고한다"를 넣는다. 턴 안에서만 쓴다. 데모 모드는 저장하지 않는다. 개발 로그에는 요약 라벨만 남긴다
4. **동의 절차**: 음성 안내 + 큰 글씨 오버레이 + **큰 `[동의하고 켜기]` / `[동의 안 함]` 터치 버튼 또는 음성 `"네"`** (§3.1 확인 흐름, `LEGAL_REVIEW.md` 시행령 §17 버튼 확인 권고 병행). 문구 예: *"카메라를 켜도 될까요? 표정으로 기분을 짐작해 대답에 참고합니다. 영상은 저장하지 않으며, 동의하지 않아도 대화할 수 있습니다."*
5. **언제든 끄기**: `"카메라 꺼 줘"` 음성 명령과 설정 패널 토글 버튼. 켜져 있는 동안 카메라 표시를 보인다 (설정에서 배지 표시도 개별 제어 가능)
6. **진단 표현 금지**: hint는 어조 지시만 한다. "우울해 보인다" 같은 진단 표현을 쓰지 않는다 (§5, 의료법 §27)
7. **확인하지 않은 법적 쟁점**: 공공장소 고정형 영상기기 금지(§25①), 영상기기 녹음 기능 금지(§25⑤)와 카메라+마이크 단말의 관계. 법률 자문이 필요하다

### 4.5 LLM hint로 넣는 방식

- 지금 방식을 그대로 쓴다: 감정 → 어조 지시 문장 → 이번 턴 요청에만 넣는다 (`llm/hint.py`, `pipeline.respond/prepare(hint=...)`)
- `emotion_hint(emotion)` 옆에 `fused_hint(voice_emotion, face_summary)`를 더한다. 반환은 `(hint 문장 | None, 규칙 번호)`다
- 문장 끝에는 지금의 단서 문구(`_NOTE`: "판단은 틀릴 수 있으니 이용자가 한 말의 내용을 먼저 따릅니다")를 항상 붙인다
- 개발 화면·로그에는 규칙 번호만 보인다. hint 문장은 내보내지 않는다

### 4.6 음성 감정과 합치는 규칙

얼굴 요약이 **유효**하려면: 동의함, 관측 비율 ≥ 기준, 신뢰도 ≥ 기준, 이번 발화 구간의 요약이어야 한다. 기준값은 F1·F3 측정으로 정한다.

| # | 음성 태그 (SenseVoice) | 얼굴 요약 | 결과 hint |
|---|---|---|---|
| R0 | 무엇이든 | 유효하지 않음 | 지금 동작 그대로: `emotion_hint(음성)` |
| R1 | 부정 (SAD·FEARFUL·ANGRY·DISGUSTED) | 같은 쪽 부정 | 음성 감정 hint. "목소리와 표정이 모두" 문형 |
| R2 | 부정 | 다른 부정 (예: SAD와 ANGRY) | 음성 감정 hint (음성 우선) |
| R3 | 중립·모름 | 부정 | 얼굴 감정 hint. "표정이 ~해 보일 수 있습니다" 약한 문형 |
| R4 | 중립·모름 | 긍정·놀람 | hint 없음 (얼굴만으로 밝은 어조를 지시하지 않는다) |
| R5 | 부정 ↔ 긍정 충돌 | 반대쪽 | 감정 이름 없는 지시: "기분을 단정하지 말고 말씀 내용에 맞춰 차분하게" |
| R6 | 긍정 | 긍정 | 음성 감정 hint (지금과 같음) |

- 감정 hint는 위기 판정에 쓰지 않는다. 위기는 텍스트 경로로만 본다 (`docs/PLAN.md` §5)
- 합성음 e2e에서 음성 감정 태그는 모두 `EMO_UNKNOWN`이었다 (`Claude/docs/STATE.md` 알려진 문제). 실제로는 R3·R4가 자주 걸릴 수 있다. 확인하지 않았다

### 4.7 지연 예산

| 구간 | 예산 (제안 합격선) | 근거·측정 |
|---|---|---|
| 표정 모델 추론 | 응답 경로 밖. 0ms | 브라우저에서 따로 돈다. 턴 경로는 요약을 기다리지 않는다 (§4.2-5) |

| LLM 첫 토큰 | 카메라 켬/끔 차이 ≤ +20ms | hint 문장 길이만큼 프리필이 는다. F3에서 ABAB로 잰다 |

| 요약 도착률 | 턴의 90% 이상에서 `prepare` 전에 도착 | 개발 로그로 센다. 미달이면 발화 중 중간 요약을 보낸다 |

## 9. 위험

1. **`session.py` 집중**: 작업 7개가 같은 파일을 고친다. 새 모듈(`intent.py`, `web/lifecycle.py`, `web/devlog.py`)로 빼고 `session.py`에는 연결만 둔다
2. **에코**: AEC 없는 스피커에서 봇 소리가 명령으로 잡힐 수 있다. 확인 질문 문구로 줄이지만 실제 효과는 D3·E1에서만 알 수 있다
3. **명령과 대화의 경계**: 고령자는 짧게 말하는 경우가 많다. "그만"이 감정 표현일 수 있다. 위기 표현 우선 검사와 확인 질문으로 줄인다. 실제 사용자 발화로 확인하지 않았다
4. **표정 모델 정확도·편향**: 공개 표정 데이터에 고령자가 적은 것으로 안다. 확인하지 않았다. 그래서 얼굴 단독 긍정은 쓰지 않고(R4), 중립 오판 수를 합격선으로 둔다
5. **태블릿 성능**: 표정 모델이 마이크 AudioWorklet과 재생을 끊을 수 있다. 언더런 카운터로 잰다
6. **법적 쟁점 미해결**: 대기 청취(통신비밀보호법), 카메라(§25), 음성 동의 효력. 이 계획은 연구실 시연 기준이다. 공공 설치 기준이 아니다. 또한 데모에서 AI 고지를 끄는 토글은 법적 경고 확인 뒤 내부 시험용으로만 쓰도록 제한한다
7. **개발 장비 수치**: 지연 수치는 GB10 값이다. 운영 PC(Windows 11 + RTX 4090 ×2)에서 다시 잰다 (`docs/PLAN.md` §4 5주차)
