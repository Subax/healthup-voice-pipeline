## 1. 1a 및 1b v2 실측 요약 (n=20, ABAB 교차, `CV_HOP=10`)

| 모드 | 첫 청크 P50/P90 | TTS 첫 소리 P50/P90 (서버 P50) | 합계(`audio`) P50/P90 | 군더더기 단독 첫 청크 | `gap_ms` P50/P90 (`gap > 0` 턴) | 판정 |
|---|---|---|---|---|---|---|

| (1b) `idle` (LLM 유휴) | 495 / 595ms | **711 / 723ms** (709ms) | **1207 / 1308ms** | 0/20 | 0 / 0ms (**0/20**) | 이론 하한선 |

| (1b) `after_chunk1_tts` | 495 / 694ms | **714 / 726ms** (712ms) | **1210 / 1404ms** (-286ms) | 0/20 | **605 / 999ms (20/20)** | ❌ `gap` 미달 |

- **원인 1 (단축 폭 한계 288ms)**: 10자 내외 첫 문장은 토큰 수가 적어 LLM 유휴 상태에서도 TTS 첫 소리가 P50 711ms다 (40문장 세트의 507ms와 다름). 양보는 이미 유휴 하한선(711ms)에 도달했다.
- **원인 2 (`after_first_frame` ≈ `after_chunk1_tts`)**: 10자 문장은 CosyVoice3가 단일 청크로 내보내므로 첫 프레임 시각(`t1 ≈ 712ms`)이 곧 1청크 합성 완료 시각이다.
- **원인 3 (`gap_ms` 20/20 발생)**: 1청크(10자) 오디오 길이 `D1`은 약 1.2~1.5초인데, `t1` 이후 2차 LLM 첫 토큰 시간 (TTFT)(193ms, 접두사 캐시 (prefix cache) 적중률 0%) + 2청크 생성(약 500ms) + 2청크 TTS 첫 소리(약 710ms)를 합치면 `t2 - t1 ≈ 1.8~2.0초`가 걸린다.

## 2. 선택지 4개 비교 (추천 1개)

### (추천) 선택지 (a): 양보 포기·동시 실행 유지 + (1a) 프롬프트·청커 보정만 기본값 승격

- **내용**: `next_01.md` 중단 조건에 따라 2단계(파이프라인·웹 양보 통합)를 하지 않는다. 검증 통과한 (1a) `PROMPT_NO_FILLER`와 `skip_filler_comma=True`만 기본값으로 올린다.
- **예상 수치**:
  - 개발 장비(단일 GB10): 첫 청크 P50 **496ms**, TTS 첫 소리 P50 **999ms**, 합계 P50 **1496ms**(기존 1650ms 대비 -154ms), 군더더기 단독 첫 청크 **0/20**, `gap_ms` P50 **0ms**(P90 554ms, 8/20). 맞장구 첫 소리는 발화 끝 P50 **349ms**에 먼저 나간다.
  - 운영 PC(RTX 4090 ×2, 그래픽 처리 장치 (GPU) 분리 시): 코드 변경 없이 `idle` 수치(TTS P50 **~711ms**, 합계 P50 **~1207ms**, `gap > 0` **0/20**)에 도달할 것으로 본다 (**확인하지 않았다**).
- **위험**: 단일 GPU 개발 장비에서는 본문 첫 오디오가 약 1.7~1.8초(e2e 기준)로 남고, 동시 실행에서도 8/20턴은 문장 사이 공백(P90 554ms)이 있다.
- **측정 방법**: `openai_stream.py`·`chunker.py` 기본값을 보정본으로 바꾼 뒤 `.venv/bin/python -m pytest`와 `bench/web_e2e.py`(4문장 × 4회, n=16)를 실행한다.

### 선택지 (b): 1청크를 길게 해서 `gap_ms` 가리기 (`first_min` 2 → 18~22자 상향)

- **내용**: 첫 청크를 18~22자(또는 두 문장)로 길게 잡아 1청크 오디오 길이 `D1`을 약 2.5초로 늘려 2차 생성·합성 시간(약 1.4~1.8초)을 가린다.
- **예상 수치 (확인하지 않았다)**:
  - 첫 청크 시각이 10자(495ms)에서 20자로 늘어나 **+300~350ms 증가(P50 약 800~850ms)**한다.
  - TTS 첫 소리가 600~710ms로 나와도 **합계(`audio`) P50은 약 1400~1550ms**가 되어 양보의 첫 소리 단축 이득(-287ms)이 사라진다. `gap_ms`만 P50 0~200ms로 줄어든다.
- **위험**: 첫 소리를 앞당기려는 목표와 정면으로 충돌하며(`docs/PLAN.md` §2 #2 위반), 첫 문장이 짧게 끝난 경우 두 번째 문장 끝까지 첫 오디오가 막힌다.
- **측정 방법**: `.venv/bin/python bench/first_audio_bench.py --first-min 12 16 20 -n 20 --compare-yield`로 `audio` P50과 `gap_ms` P50을 측정한다.

### 선택지 (c): 2청크 생성 앞당기기 (1차에서 1청크+일부 토큰 생성 후 중단 / vLLM 접두사 캐시 활성화)

- **내용**: ① 1차 LLM 요청을 1청크 직후가 아니라 1청크 뒤 +8~12토큰(약 250ms 추가) 또는 2청크 끝까지 받고 끊거나, ② vLLM 접두사 캐시 적중률(현재 0%)을 고쳐 2차 TTFT(193ms)를 줄인다. (`produce_phase2`는 이미 2청크 직후 스트림을 닫아 2청크 TTS 때 LLM 경합이 없는 상태다.)
- **예상 수치 (확인하지 않았다)**:
  - 접두사 캐시만 고칠 경우: 2차 TTFT 193ms 중 최대 100~150ms만 줄어 `gap_ms` P50은 **약 450~600ms(`gap > 0` 여전히 18~20/20)**로 남는다.
  - 1차에서 2청크 끝까지 받고 끊을 경우: 1청크 TTS 초반 400~500ms 동안 LLM과 겹쳐 1청크 TTS가 712ms → **약 850~900ms**(합계 P50 약 1350~1400ms, 단축 폭 -100~150ms로 반감)가 되는 대신 `gap_ms`는 **0/20**으로 줄어든다.
- **위험**: 단일 GPU에서는 1청크 TTS 시간(0~712ms) 안에 2차 LLM이 돌면 그만큼 1청크 TTS가 다시 느려지는 영합(zero-sum) 관계라, 코드 복잡도 대비 실익이 작다.
- **측정 방법**: `first_audio_bench.py`에 `yield_after_chunk2` 모드를 추가해 `.venv/bin/python bench/first_audio_bench.py --first-min 2 -n 20 --compare-yield`로 합계 P50과 `gap_ms`를 측정한다.

### 선택지 (d): 기타 — 문장 경계 0.6초 쉼 청취 판정 + CosyVoice 취소 잠금(1.4초) 수정

- **내용**:
  1. **문장 경계 쉼 청취 판정**: `after_chunk1_tts`의 `gap_ms`(P50 605ms)는 단어 중간 끊김이 아니라 **완결된 첫 공감 문장(`"많이 힘드셨겠어요."`) 마침표 뒤의 쉼**이다. 고령자 상담 말투에서 첫 문장 뒤 0.6초 호흡이 자연스럽게 들리는지 사람이 들어 보고 결정한다 (`next_01_review.md` §1단계 코드 검토 결론과 동일).
  2. **CosyVoice 취소 뒤 잠금 대기(약 1.4초) 수정 (`next_01_review.md` K-7)**: 클라이언트 취소(`cancel()`) 뒤에도 서버가 약 1.4초 동안 합성을 계속해 끼어들기 (barge-in) 직후 새 턴의 첫 TTS를 늦출 수 있으므로, `services/cosyvoice/server.py`의 취소 확인 주기를 줄인다.
- **예상 수치**:
  - 청취에서 0.6초 문장 쉼이 허용되면 `after_chunk1_tts`로 첫 오디오 합계 P50 **1210ms**(-286ms, P90 -369ms)를 얻는다.
  - CosyVoice 취소 즉시 중단 시 끼어들기 직후 다음 턴의 TTS 잠금 대기(최대 ~1.4초)가 사라진다 (**확인하지 않았다**).
- **위험**: 사람 귀에 0.6초 쉼이 어색하게 들리면 양보는 쓸 수 없다 (청취 전까지 **확인하지 않았다**).
- **측정 방법**: 아래 §3의 청취 샘플 WAV 9개를 생성해 사람이 블라인드 비교하고, CosyVoice 취소 후 잠금 해제 시간은 서버 로그 타임스탬프로 확인한다.

## 4. 권장 실행 순서

1. **(즉시 가능)** 합격 판정을 받은 (1a) 프롬프트·청커 보정(`PROMPT_NO_FILLER`, `skip_filler_comma=True`)을 기본값으로 올리고 `.venv/bin/python -m pytest`를 통과시킨다.
2. **(양보 보류)** LLM 양보(`--llm-yield`)는 2단계 파이프라인 통합을 보류하고 기본 끔(동시 실행 유지)으로 둔다.
3. **(청취 샘플 생성)** 위 §3의 비교 WAV 12개를 `bench/results/next_02_listen/`에 생성해 두고, 사용자의 `docs/PLAN.md` §3 청취 세션에서 문장 사이 0.6초 쉼 허용 여부를 함께 결정한다.
4. **(다음 독립 작업)** 사용자 녹음·청취·태블릿 IP 없이 진행할 다음 작업으로 ① `services/cosyvoice/server.py` 취소 후 잠금 대기(1.4초) 단축 또는 ② `docs/LEGAL_REVIEW.md` P0(판단 로그 전사 저장 기본 끔 + 위기 키워드 고정 경로)로 넘어간다.
